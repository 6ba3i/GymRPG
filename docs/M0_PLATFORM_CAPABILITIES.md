# M0 platform diagnostics and gates

M0 reports read-only Android API/device/renderer/shader status, notification promotion eligibility, and visibility of the mainland Xiaomi HealthKit package. The UI can display `CapabilityDiagnostics.read(activity)` from `:core:integrations`, `NotificationCapability.read(context)` from `:core:notifications`, and `XiaomiHealthKitProbe.read(context)` from `:integration:xiaomi-cn`. For a common list, wrap the notification string with `CapabilityFact("Live Updates", NotificationCapability.read(context))`.

The app's merged manifest declares `<queries><package android:name="com.xiaomi.healthkit" /></queries>` through the optional Xiaomi module; no broad package visibility or protected service introspection is used. A visible package establishes only visibility, **not** authorization, approved scopes, signing identity, user consent, bound service, or available mainland Mi Fitness data. A package reported absent can also reflect package visibility restrictions or a missing installation. M0 contains no proprietary SDK, no health reads, and no global Mi Fitness inference. Subsequent implementation requires Xiaomi developer registration, approved app and scopes, aligned debug/release signing certificate fingerprints, user consent, permitted SDK redistribution, and verification on the Chinese ROM.

On API 36+, the notification manager can report whether the app may post promoted notifications. Android promotion depends on a qualifying ongoing notification, permissions, runtime rules, and OEM rendering. M0 does not post one or claim island behavior. When ineligible, a user-started workout in a later milestone can request notification permission in context and use a standard persistent notification; API 35 and older use that fallback. Foreground service implementation waits for the later workout feature and platform policy review.

**Official references:** [Android Live Updates](https://developer.android.com/develop/ui/views/notifications/live-update), [Android package visibility declarations](https://developer.android.com/training/package-visibility/declaring), [Xiaomi HyperOS HealthKit client guide](https://dev.mi.com/xiaomihyperos/documentation/detail?pId=2332). These describe capabilities and approval requirements, not acceptance of this app by Xiaomi.

**Validation evidence:** see `m0-evidence/M0_TEST_RESULTS.md` for device/API, ROM, screenshot and test results. Actual HealthKit package visibility and notification promotion eligibility have not been captured as acceptance evidence. M0's package visibility and promotion probes alone cannot verify HealthKit authorization or HyperIsland display.
