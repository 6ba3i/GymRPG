# M0 implementation tickets

Scope: technical proof in the existing repository root. Preserve specification, bootstrap sources and skill configuration. M1 domain persistence/onboarding, real workouts, scoring, nutrition and health import are excluded.

- M0-01 Toolchain: pin a compatible SDK 37 / JDK 17 / AGP / Gradle / Kotlin stack, wrapper checksum and root modules. Acceptance: clean debug APK, unit tests and lint.
- M0-02 Visual foundation: independently authored Google Sans Flex scale, font license in APK, Full/Efficient wrappers, five destination shell. Acceptance: font axes/provenance checks and screenshots of both modes.
- M0-03 Anatomy: audited front/back paths with explicit taxonomy mapping, native rendering, selection, bounded zoom/reset and semantic alternative. Acceptance: mapping/geometry checks, interaction tests, both view screenshots.
- M0-04 Platform: public capability probes, narrow HealthKit package visibility, optional adapter boundary, standard Live Update eligibility and documented fallback. Acceptance: device/API/inset report; no claim of authorization or OEM island promotion.
- M0-05 Verification: unit and Compose instrumentation, inset/IME test harness, CI, physical smoke and evidence. Acceptance: actual results recorded, gaps explicit, original files preserved.

Architecture: app owns navigation and demo settings; core/designsystem owns rendering/font; feature/anatomy owns the SVG proof; core/integrations and core/notifications own capability contracts; integration/xiaomi-cn owns the optional package probe. No server or required network permission. Room begins with M1's real entity requirements, rather than speculative M0 tables.
